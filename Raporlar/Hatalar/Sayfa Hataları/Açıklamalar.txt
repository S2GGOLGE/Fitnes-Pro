# FITNESS PRO — HAMBURGER MENÜ, ICON VE BİLDİRİM SİSTEMİ DÜZELTMELERİ

## Genel Talimatlar

Fitness Pro frontend projesinde aşağıdaki 3 sorunu detaylı şekilde analiz et ve düzelt.

**ÖNEMLİ KURALLAR:**

* Mevcut tasarım sistemini bozma.
* Index.html ile diğer sayfaların hamburger menü tasarımını tutarlı tut.
* Mevcut renk paletini, responsive yapıyı ve CSS mimarisini koru.
* Sorunların yalnızca geçici olarak değil, kök nedenleriyle çözülmesini sağla.
* Çalışan özellikleri bozma.
* Gereksiz dosya oluşturma veya mevcut yapıyı yeniden yazma.
* Önce ilgili HTML, CSS ve JavaScript dosyalarını incele, ardından değişiklik yap.
* Tüm düzeltmeler tamamlandıktan sonra farklı ekran boyutlarında ve menü durumlarında test gerçekleştir.

# 1. ICON HATASI — BAZEN GÖRÜNÜYOR, BAZEN GÖRÜNMÜYOR

### Sorun Tanımı

Frontend içerisinde kullanılan ikonlar bazı durumlarda düzgün görüntüleniyor, bazı durumlarda ise hiç görünmüyor veya tutarsız şekilde render ediliyor.

Sorun aşağıdaki durumlardan kaynaklanıyor olabilir:

* İkon kütüphanesinin yüklenme sırası.
* Lucide ikonlarının DOM'a sonradan eklenmesine rağmen yeniden initialize edilmemesi.
* `data-lucide` attribute'larının yanlış kullanımı.
* Dinamik olarak oluşturulan HTML içeriklerinde ikonların initialize edilmemesi.
* JavaScript hata veya çalışma sırası problemleri.
* CSS tarafından ikonların gizlenmesi.
* SVG genişlik, yükseklik, `display` veya `stroke` özelliklerinin bozulması.
* Birden fazla ikon sisteminin tutarsız şekilde kullanılması.

### Yapılacak İşlemler

1. Projede kullanılan ikon sistemini tespit et.

   * Lucide Icons kullanılıyorsa mevcut entegrasyonu incele.
   * Emoji, Unicode karakterleri veya farklı ikon kütüphaneleriyle karışıklık olup olmadığını kontrol et.
   * Projenin mevcut ikon standardına uygun şekilde ilerle.

2. İkonların initialize edilme sürecini analiz et.

   * Sayfa ilk yüklendiğinde ikonların görünmesini doğrula.
   * Hamburger menü açılıp kapatıldığında ikonların kaybolmadığını kontrol et.
   * Dinamik olarak oluşturulan bildirim, menü veya profil alanlarındaki ikonları test et.
   * DOM değişikliklerinden sonra gerekli ikon render sürecinin çalıştığından emin ol.

3. İkonların CSS stilini kontrol et.

   * `width`, `height`, `display`, `visibility`, `opacity` ve `stroke` değerlerini incele.
   * İkonların arka planla aynı renkte kalıp kalmadığını kontrol et.
   * `overflow: hidden` veya `z-index` kaynaklı görünürlük sorunlarını araştır.
   * İkonların farklı ekran boyutlarında kaybolmasını engelle.

4. JavaScript konsol hatalarını kontrol et.

   * İkon kütüphanesi yüklenmeden fonksiyon çağrılıyor mu?
   * İkon render işlemi sırasında hata oluşuyor mu?
   * Bir sayfada çalışan kodun diğer sayfaları etkileyip etkilemediğini incele.

### Beklenen Sonuç

* Tüm ikonlar tutarlı şekilde görünmeli.
* Sayfa ilk açıldığında ikonlar çalışmalı.
* Hamburger menü açılıp kapatıldığında ikonlar kaybolmamalı.
* Dinamik içeriklerde kullanılan ikonlar doğru şekilde render edilmeli.
* Konsolda ikonlarla ilgili JavaScript hatası bulunmamalı.
* Mevcut ikon tasarımı ve boyutları korunmalı.

# 2. INDEX.HTML — HAMBURGER MENÜ KAPATILDIĞINDA ICON EN ALT KISMA TAŞINACAK

### Sorun Tanımı

`index.html` sayfasında hamburger menü açıkken sidebar / navigasyon alanı görüntüleniyor. Menü kapatıldığında hamburger menü ikonu belirlenen alt konuma taşınmalı.

**İstenen davranış:**

* Hamburger menüsü açıkken mevcut tasarım ve yerleşim korunacak.
* Hamburger menüsü kapatıldığında hamburger ikonu sidebar'ın / menü alanının en alt bölümünde bulunacak.
* İkon, menü kapalı durumdayken görünür ve erişilebilir kalacak.
* İkonun konumu, diğer içeriklerin üzerine binmemeli.
* Responsive ekranlarda konum tutarlılığı korunmalı.

### Yapılacak İşlemler

1. `index.html` içerisindeki hamburger menü HTML yapısını analiz et.
2. İkonun hangi container içerisinde bulunduğunu tespit et.
3. Sidebar açık ve kapalı durumlarında kullanılan CSS sınıflarını incele.
4. Menü kapalı durumuna özel bir stil veya mevcut state yapısını kullan.
5. Hamburger ikonunun alt konumlandırmasını sağla.

### Konumlandırma Kuralları

* Menü kapalıyken hamburger ikonu, menü alanının en alt kısmına yerleşmeli.
* Eğer sidebar `display: none` ile tamamen kaldırılıyorsa, hamburger ikonunun görünür kalmasını sağlayan uygun bir container yapısı oluştur.
* `position: absolute` veya `position: fixed` kullanılıyorsa, konumlandırma referansını ve responsive davranışı dikkatli şekilde kontrol et.
* İkonun alt kısma taşınması diğer menü öğelerinin hizasını bozmamalı.
* `z-index`, `bottom`, `left` ve `transform` değerleri gerektiğinde kontrol edilmeli.
* Mobil ve masaüstü ekranlarda farklı konumlandırma gerekiyorsa mevcut responsive yapıya uygun çözüm uygula.

### Beklenen Sonuç

**Menü açıkken:**

* Mevcut hamburger menü tasarımı korunacak.
* Menü elemanları mevcut konumlarında kalacak.

**Menü kapalıyken:**

* Hamburger ikonu menü alanının en alt kısmında bulunacak.
* İkon görünür ve tıklanabilir olacak.
* Menü yeniden açıldığında tasarım eski konumuna doğru şekilde dönecek.
* Sayfa içeriği ve diğer bileşenler etkilenmeyecek.

# 3. BİLDİRİM SİSTEMİ — "MEVCUT BİLDİRİM YOK" DIV GÖRÜNÜRLÜK KONTROLÜ

### Sorun Tanımı

Bildirim sistemi içerisinde bildirim bulunmasına rağmen `Mevcut bildirim yok` mesajını gösteren div görünmeye devam ediyor.

İstenen davranış:

**Bildirim varsa:**

* `Mevcut bildirim yok` div'i gizlenecek.
* Bildirim listesi görüntülenecek.
* Bildirim sayısı doğru şekilde gösterilecek.

**Bildirim yoksa:**

* `Mevcut bildirim yok` div'i görünür olacak.
* Bildirim listesi boş durumda kalacak veya uygun şekilde gizlenecek.
* Kullanıcıya doğru boş durum mesajı gösterilecek.

### Yapılacak İşlemler

#### 3.1. HTML Yapısını Analiz Et

Bildirim bileşeninde bulunan aşağıdaki alanları tespit et:

* Bildirim container'ı.
* Bildirim listesi.
* `Mevcut bildirim yok` div'i.
* Bildirim sayacı / badge.
* Bildirimlerin dinamik olarak eklendiği alan.

Mevcut HTML yapısını gereksiz yere değiştirme.

#### 3.2. JavaScript Bildirim Kontrolü

Bildirimler API'den veya JavaScript veri kaynağından alındıktan sonra liste uzunluğunu kontrol et.

Örnek mantık:

```javascript
const hasNotifications = notifications.length > 0;

emptyState.style.display = hasNotifications ? "none" : "";
notificationList.style.display = hasNotifications ? "" : "none";
```

**Not:** Bu örnek mevcut projeye doğrudan kopyalanmak zorunda değildir. Mevcut CSS, HTML ve state yönetimine uygun şekilde uygula.

Kontrol edilmesi gereken durumlar:

* API başarılı şekilde bildirim döndürdüğünde.
* API boş bildirim listesi döndürdüğünde.
* API hata verdiğinde.
* Bildirimler yüklenirken.
* Bildirimler okundu olarak işaretlendiğinde.
* Bildirim silindiğinde.
* Bildirimler dinamik olarak güncellendiğinde.
* Sayfa yenilendiğinde.

#### 3.3. Veri Kontrolü

Bildirim listesinin aşağıdaki veri yapılarına karşı dayanıklı olduğundan emin ol:

* `[]` — Boş dizi.
* Bir veya daha fazla bildirim içeren dizi.
* `null` veya `undefined` dönen veri.
* API yanıtı içerisinde bildirim listesinin farklı bir property altında bulunması.

API'nin gerçek response yapısını incele. Property isimlerini tahmin ederek değiştirme.

#### 3.4. CSS Görünürlük Yönetimi

Bildirim boş durumunun gizlenmesi için mevcut CSS sistemine uygun yaklaşım kullan.

Kontrol edilecekler:

* `display: none`.
* `visibility: hidden`.
* `opacity`.
* `hidden` attribute.
* CSS sınıfları.
* `!important` nedeniyle JavaScript stilinin etkisiz kalması.
* Bildirim listesinin boşken veya doluyken doğru görünür olması.

**Önemli:** `Mevcut bildirim yok` div'i bildirimler mevcutken DOM'da bulunabilir; ancak kullanıcıya görünmemelidir. Erişilebilirlik açısından gerekli durumlarda `hidden` attribute veya uygun görünürlük yönetimi kullan.

#### 3.5. Bildirim Sayacı

Bildirim badge'i varsa:

* Bildirim sayısını gerçek listeyle senkronize et.
* Bildirim bulunmuyorsa sayaç değerinin uygun şekilde gizlenmesini veya sıfırlanmasını sağla.
* Okunmamış bildirim sayısı ile toplam bildirim sayısını birbirine karıştırma.
* Mevcut backend response yapısını ve iş mantığını değiştirme.

### Beklenen Sonuç

| Durum                             | Bildirim Listesi    | Boş Durum Div'i                                                           |
| --------------------------------- | ------------------- | ------------------------------------------------------------------------- |
| Bildirim yok                      | Gizli veya boş      | Görünür                                                                   |
| 1 bildirim                        | Görünür             | Gizli                                                                     |
| Birden fazla bildirim             | Görünür             | Gizli                                                                     |
| API boş dizi döndürür             | Gizli veya boş      | Görünür                                                                   |
| API hata verir                    | Hata durumuna uygun | Yanlışlıkla "bildirim yok" gösterilmemeli; mevcut hata tasarımı korunmalı |
| Bildirim silinir ve liste boşalır | Gizli veya boş      | Görünür                                                                   |
