# FITNESS PRO — HARİTALAR SAYFASI FRONTEND TASARIMI

Fitness Pro projesine yeni bir **Haritalar** sayfası tasarlanacaktır.

## ÖNEMLİ KURAL

Bu çalışma **SADECE FRONTEND** kapsamındadır.

Şu aşamada:

* Backend yazılmayacak.
* API oluşturulmayacak.
* API bağlantısı yapılmayacak.
* Database kullanılmayacak.
* JWT/auth backend entegrasyonu yapılmayacak.
* Endpoint oluşturulmayacak.
* Backend dosyaları değiştirilmeyecek.
* Mevcut backend sistemi incelenip değiştirilmek zorunda değildir.

Tüm kullanıcı verileri ve harita üzerindeki kişiler **frontend mock verileri** ile simüle edilmelidir.

Daha sonraki aşamada backend entegrasyonu yapılabilecek şekilde temiz ve modüler frontend kodu hazırlanmalıdır.

---

# 1. YENİ SAYFA

Yeni sayfa:

`Haritalar.html`

`Css/UI/Haritalar.css`

`JavaScripts/UI/Haritalar.js`

Mevcut proje yapısına ve isimlendirme sistemine uyulmalıdır.

# 2. TASARIM REFERANSI

Haritalar sayfası mevcut Fitness Pro tasarımının bir parçası gibi görünmelidir.

Özellikle:

* Goals.html
* Profile.html
* Workouts.html
* Progress.html
* Ayarlar.html

Yeni ve bağımsız bir tema oluşturulmamalıdır.

Mevcut:

`DesignSystem.css`

kullanılmalıdır.

# 3. HAMBURGER MENÜ

Haritalar sayfasındaki hamburger menü diğer sayfalardaki hamburger menüyle aynı olmalıdır.

Yeni bir hamburger menü tasarımı oluşturulmayacaktır.

Menü:

* Aynı konumda
* Aynı boyutta
* Aynı animasyonda
* Aynı açılıp kapanma mantığında
* Aynı ikon sisteminde
* Aynı responsive davranışta

çalışmalıdır.

Haritalar sayfası menü içerisinde diğer sayfalarla **eşit seviyede** bulunmalıdır.

Örneğin mevcut navigasyon yapısına uygun olarak:

```text
Ana Sayfa
Profil
Antrenmanlar
İlerleme
Hedefler
Arkadaşlar
Haritalar
Mesajlar
Bildirimler
Ayarlar
```

Haritalar aktif sayfayken ilgili menü öğesi aktif görünmelidir.

Mevcut navigasyon yapısı değiştirilmemeli, sadece Haritalar sayfası sisteme uygun şekilde eklenmelidir.

---

# 4. SAYFA BAŞLIĞI

Sayfanın üst kısmında:

**Haritalar**

başlığı bulunmalıdır.

Alt açıklama:

**Yakınındaki arkadaşlarını ve antrenörleri keşfet.**

şeklinde olabilir.

Başlık yapısı Goals.html ile aynı görsel hiyerarşiyi kullanmalıdır.

---

# 5. ANA HARİTA

Sayfanın ana bölümü harita olmalıdır.

Harita ekranın mümkün olduğunca büyük kısmını kullanmalıdır.

Örnek yapı:

```text
┌─────────────────────────────────────────────┐
│ ☰                                           │
│                                             │
│                 HARİTALAR                   │
│      Yakınındaki kişileri keşfet.           │
│                                             │
├─────────────────────────────────────────────┤
│                                             │
│ [ Tümü ] [ Arkadaşlar ] [ Antrenörler ]    │
│                                             │
│                                             │
│              ●                              │
│                                             │
│                     ◎                       │
│                                             │
│                            ●                │
│                                             │
│                                     ●       │
│                                             │
│                                  [ ◎ ]      │
│                                             │
└─────────────────────────────────────────────┘
```

Harita gerçek bir harita servisi kullanılabiliyorsa kullanılabilir.

Ancak bu aşamada gerçek kullanıcı konum verileri veya backend verileri kullanılmayacaktır.

Gerekirse harita alanı frontend prototipi/mock harita görünümüyle hazırlanabilir.

---

# 6. KULLANICININ KENDİ KONUMU

Kullanıcının kendi konumu harita üzerinde diğer kişilerden farklı bir marker ile gösterilmelidir.

Marker:

* Daha belirgin
* Kolay fark edilebilir
* Fitness Pro tasarımına uygun
* Emoji içermeyen
* SVG/Lucide ikon kullanan

bir yapıda olmalıdır.

Örneğin:

```text
◎
```

şeklindeki görsel mantık kullanılabilir.

Marker'ın yanında:

**Sen**

gibi bir etiket bulunabilir.

---

# 7. TARAYICI KONUMU

Frontend aşamasında kullanıcı isterse tarayıcının:

`navigator.geolocation`

özelliği kullanılarak kendi konumu alınabilir.

Bu özellik yalnızca **kullanıcının kendi konumunu haritada göstermek** amacıyla kullanılacaktır.

Konum herhangi bir backend'e gönderilmeyecektir.

Konum alınamazsa sayfa bozulmamalıdır.

Örneğin:

**Konumun alınamadı.**

mesajı gösterilebilir.

Kullanıcı isterse:

**Konumumu Bul**

butonuna basarak tekrar deneyebilmelidir.

---

# 8. KENDİ KONUMUNA DÖN BUTONU

Haritanın uygun bir köşesinde konum butonu bulunmalıdır.

Örneğin:

```text
┌─────┐
│  ◎  │
└─────┘
```

Butona basıldığında harita kullanıcının kendi konumuna odaklanmalıdır.

Bu buton mobil cihazlarda da kolay kullanılabilir olmalıdır.

---

# 9. YAKINDAKİ KİŞİLER

Harita üzerinde kullanıcıya yakın kişiler gösterilecektir.

İki kullanıcı tipi olacaktır:

### Arkadaş

Kullanıcının arkadaşları.

### Antrenör

Fitness Pro içerisindeki antrenörler.

Bu kişiler frontend içerisinde **mock data** olarak oluşturulmalıdır.

Örnek:

```javascript
const nearbyUsers = [
    {
        id: 1,
        username: "fitness_master",
        profilePhoto: "assets/profiles/default.svg",
        type: "friend",
        latitude: 38.355,
        longitude: 38.309
    },
    {
        id: 2,
        username: "coach_ali",
        profilePhoto: "assets/profiles/default.svg",
        type: "trainer",
        latitude: 38.362,
        longitude: 38.315
    }
];
```

Gerçek kullanıcı verileri kullanılmayacaktır.

---

# 10. PROFİL FOTOĞRAFI

Harita üzerindeki kişi markerlarında kullanıcının profil fotoğrafı gösterilmelidir.

Örneğin:

```text
    ┌───────┐
    │ FOTO  │
    └───────┘
        ●
```

Profil fotoğrafı bulunmadığında varsayılan Fitness Pro profil görseli kullanılmalıdır.

Kırık görsel durumunda fallback uygulanmalıdır.

---

# 11. USERNAME

Kullanıcının profil fotoğrafının yanında veya bilgi kartında:

`Username`

gösterilmelidir.

Örneğin:

```text
@fitness_master
```

Username mock veriden alınmalıdır.

Gerçek ad ve soyad zorunlu değildir.

Bu sayfanın temel kullanıcı tanımlayıcısı Username olmalıdır.

---

# 12. MARKER'A TIKLAMA

Harita üzerindeki bir kullanıcı markerına tıklandığında küçük bir kullanıcı bilgi kartı açılmalıdır.

Örneğin:

```text
┌────────────────────────────┐
│       [ PROFİL ]           │
│                            │
│       @fitness_master      │
│       Arkadaş              │
│                            │
│       350 m uzaklıkta      │
│                            │
│       [ Profili Gör ]      │
└────────────────────────────┘
```

Bilgi kartında:

* Profil fotoğrafı
* Username
* Kullanıcı tipi
* Yaklaşık mesafe
* Profili Gör butonu

bulunabilir.

# 14. FİLTRE SİSTEMİ

Haritanın üst kısmında filtre butonları bulunmalıdır:

```text
[ Tümü ] [ Arkadaşlar ] [ Antrenörler ]
```

### Tümü

Mock arkadaş ve antrenörlerin tamamını gösterir.

### Arkadaşlar

Sadece `friend` tipindeki kullanıcıları gösterir.

### Antrenörler

Sadece `trainer` tipindeki kullanıcıları gösterir.

Filtre değiştiğinde sayfa yenilenmemelidir.

Markerlar ve kullanıcı listesi anında güncellenmelidir.

Aktif filtre Fitness Pro'nun primary yeşil rengiyle belirtilmelidir.
